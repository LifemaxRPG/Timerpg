# G007: The plan language (how companions and NPCs act)

- Assignee: gemini
- Type: engineering
- Branch: `gemini/G007-plan-language`
- Status: accepted

## Why it matters
The owner wants companions and important NPCs who can do almost anything a person could, chosen and sequenced by the
on-device model (Qwen on the NPU), but never able to do the impossible. Design: docs/IDEAS.md, "A plan language:
compose anything from small parts" and "NPC actions: a scripted library, chosen by the model". Read both first. Your
crime core (src/crime/) is one of the systems these plans act on.

## What to build: `src/plan/` (TypeScript, pure and deterministic, tested)
1. **The language.** A small, strict text syntax, as drafted in IDEAS.md:
   - plans with `then` and `while`;
   - steps made of: verb, target, `with` item, manner, `until` condition, `if` condition;
   - about 30 verbs to start;
   - targets as ids (`person:<id>`, `place:<id>`, `item:<id>`, `vehicle:<id>`, `player`, `nearest(<kind>)`, `here`);
   - conditions (`sees`, `at`, `time`, `heard`, `has`, `alone`, `done`).
   Write the grammar twice: as a parser in TS, and as a llama.cpp GBNF grammar file (`src/plan/plan.gbnf`) so the model
   can only produce valid plans. A test checks that both accept and reject the same samples.
2. **Name checking.** `bind(plan, facts)` resolves every id against the facts the model was given. Unknown ids,
   items the actor doesn't have and unknown places are rejected with a clear reason the model can read and fix
   ("item:key_7 unknown; known items: ...").
3. **Execution against a world interface.** `step(planState, world, actor, dt)` runs one step at a time against a
   small `PlanWorld` interface:
   - where things are;
   - can the actor see X;
   - is a door locked;
   - inventory;
   - time;
   - a simple movement model.
   Each verb has preconditions and effects. A failed step returns a structured failure ("blocked: door_3 locked") for
   replanning. `until` and `while` work. A trait gate lets an actor refuse a step by its traits (for example, a gentle
   person won't `attack`), with a reason.
4. **A stub world for tests:** a few rooms, doors with locks and keys, two guards on a patrol, a player and a companion.
   Use it to run these scenarios:
   - "keep the guard talking while I go round the back";
   - "when I signal, unlock the gate and bring the van";
   - "follow him quietly and tell me where he goes";
   - a plan that fails (locked door) and a replan that succeeds (find the key first);
   - a refusal by traits.
5. **Determinism and saves:** the plan state is plain JSON and the same inputs give the same results.

## Tests
`npx vitest run src/plan`. You can run these.
- The parser and the grammar agree (at least 30 samples each, valid and invalid).
- Binding catches every unknown id.
- All five scenarios run to their expected outcome, deterministically.
- `step` allocates little and takes under 0.05 ms per step for 50 actors.
