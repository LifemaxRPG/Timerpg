## Why it matters
G009 and G011 both landed first try. Right now the facade has its own compact police (`src/loop/policeAdapter.ts`),
because G009 wasn't merged when you wrote it. This task makes the loop run on the real G009 police. It also adds three
of your own ideas, so the town reacts in more ways the player can trace.

**The player's first encounter:** they're booked for a 2-a.m. window break and fingerprinted. The next morning a
detective links the prints to a burglary from the year before, and the pawn shop's ledger puts a stolen watch in their
hands.

## What to build
1. **One police.** Replace `src/loop/policeAdapter.ts` with calls into `src/police/` (`createPoliceForce`,
   `stepPoliceTick`, the spotting and arrest records). Keep every public `src/loop/` signature and the `TimerpgSim`
   names in `bridge.ts` unchanged, so the phone's side doesn't move. Delete the duplicate code. All G011 tests stay
   green, unchanged except where the real police behaves more richly (explain each changed expectation in
   DELIVERY.md).
2. **The booking pipeline (your G009 idea).** When an arrest completes with `transportedToStation`, book the player:
   - prints, and DNA where the era has it, go into G008 `identityFiles` via `enrollOnFile`;
   - G008's cold-case re-examination runs, so an old unsolved case can crack on the next tick;
   - `arrest()` returns what booking found, as plain-English facts for the game to show.
3. **Civilians call it in (your G011 idea).** `civilianSpotted(sim, personId, sighting)` and a `TimerpgSim` method
   for it: a person whose attitude is `report_on_sight` and who sees the player reports by the era's means (G005
   latency), which can send an officer.
4. **Small saves (your G011 idea).** Prune what resolved crimes no longer need (`toldPairs` and the like) at
   `arrest()` and `save()`. Show a 100-day save's size before and after.

5. **What the game's wiring found** (Claude wired your facade into the Android game on the real capital: 183 people, 63
   places, 96 junctions. It works end to end. These are the places where the game had to work around the API, so fix
   them in `src/loop/`; the Kotlin side will drop its workarounds):
   - `arrest()` moves the clock by the hours held, but runs no gossip, reports or decay for that time, and its result
     has no day and hour. Run the skipped time the way `advance` does, and return the new day and hour.
   - `work_shift` doesn't move time; the game calls `advance` itself for the shift's hours. Choose one owner of the
     clock and document it (Claude's preference: `act` for a shift advances the hours itself and returns the changes).
   - Patrol beats are cut from consecutive node ids, which scatters a beat across the real town. The game renumbers
     junctions along a Hilbert curve to compensate. Build beats by graph distance (nearby corners), so any numbering
     works.
   - `LoopPlaceInit` can't list staff beyond the owner. Add `staff: personId[]` (clerks, coworkers), who see what
     happens in the shop and know the player after a shift.
   - Selling a stolen item comes back with `legit: true`; only `pawnTraceFlagged` shows it was hot. Make `legit`
     false (or add `hot: true`) when the item was stolen.
   - Facts say "this person" for the player; the HUD rewords them. Take an optional player name or description in
     `init`, and use "you" in the facts the person would say to the player.
   - `spotted` gives `approach_and_question` for a matching description even on a weak case, and the stand-in arrest
     then gives 12 hours in a cell. Make questioning a real stop: papers, questions, then released or arrested by case
     strength. How harsh to be is the owner's call; keep it a tunable table.
