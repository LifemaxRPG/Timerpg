# G004: Make the zero-allocation animation test robust under load

- Assignee: gemini
- Type: engineering
- Branch: `gemini/G004-alloc-test`
- Status: hold

## Brief
`LandmarkAnimationTest.perFrameUpdateAllocatesZeroBytes` passes on its own (3 of 3 runs) but failed once inside the
full `:desktop:crossroadsTest` run on a loaded 4-core server (832 bytes over 500 frames): late JIT/deoptimisation work
lands inside the measured window. Make the test reliable without weakening what it proves:
- e.g. measure several 500-frame windows after warm-up and assert the **minimum** (or the last N windows) is 0 bytes;
  and/or assert per-frame allocation is 0 in the steady state while allowing a bounded one-off in the first window only,
  with the reason in a comment. Do not raise the threshold above 0 for the steady-state check.
- Keep the 5000-frame warm-up.
